## 本地验证

- 环境：Windows，Node 22.16.0，pnpm 10.26.2，真实 SQLite。
- `pnpm lint`、`pnpm typecheck`、`pnpm build` 通过；冻结锁文件安装通过。
- `pnpm test`：**194 项测试、24 个文件全部通过**（本轮新增 53 项）；`pnpm smoke:kernel`：**23/23**。
- 额外收尾回归：关闭与用户消息落盘交错、重置与切换串行、安装失败后恢复操作、普通空消息不误标生成；`src/preload/index.test.ts` 校验作用域和 flush 回执，`src/renderer/src/hooks/useSavedAction.test.ts` 校验重试保存与取消切换。
- 性能复测：1,200 条消息，选中状态修改 **11.2ms**；消息行和 FTS 写入 **0**，仅更新页面索引行。CI 断言写入次数和数据正确性，不把机器耗时当作稳定门槛。
- 故障测试全部使用临时工作区及测试模型；没有连接真实模型或修改已有用户数据。
- 实际 CI 和发布任务未在远端触发；本地执行对应检查，工作流已加入发布依赖。

## Electron 界面验收状态

已启动生产构建，并用独立临时账户、两个聊天页、暂停队列和本地模型准备验收。通过无障碍树确认应用加载成功，页面、标签和表格均存在；表格保留四列、首尾空值及 `x|y`。

完整交互验收**未完成**。本机窗口捕获先后返回 `FrameArrived timed out`、`window capture timed out`；点击返回 `coordinate input geometry is unavailable`。因此多页发送、队列停止、账户切换、关闭重开、备份恢复、重置和 CSV 预览的鼠标流程不能记为已通过。对应内核和镜像行为已覆盖自动化回归，仍需在可用的桌面输入通道完成交互验收。

## 恢复与限制

- 保存失败的回答保留在当前内核和镜像中。正常关闭会被阻止，用户可重试；强制终止进程或系统断电仍可能丢失尚未落盘的数据。
- 损坏索引保留为 `.pointer/index.db.corrupt-*`；原 Markdown 和队列文件不作为索引恢复的删除对象。
- 导入不是跨所有文件的事务。部分失败会显示已完成数量并停止；界面不会自动重新提交整批。
